# FreeKV: Boosting KV Cache Retrieval for Efficient LLM Inference

来源：[ICLR 2026 正式版 PDF](https://proceedings.iclr.cc/paper_files/paper/2026/file/5137e40ee586c4f1fc3615cf8cee4f87-Paper-Conference.pdf)。阅读范围：正文第 1–7 节及附录 A–C 的实验设置与消融。下文页码均为 PDF 页码。重点看解码器在哪一步等 KV，以及 FreeKV 怎样减少这段等待。

## §1–2　KV 留在主存，为什么解码还是慢？

永久丢弃 KV 不必再搬数据，但生成到后半段时，刚好需要的旧 token 可能已经找不回来了。检索方案保留完整 KV，每个解码步只读一部分。代价是要等当前层的 query 算出来，再挑页、从主存拉回数据，最后才能开始 attention。图 1–2（PDF 第 2–3 页）把这段等待画得很清楚：ArkVale 的召回串在计算前面；ShadowKV 只搬 V、在设备端重建 K；InfiniGen 根据相邻层的隐状态重新投影 query，给下一层预取。FreeKV 改用同一层的上一个解码步，不需要为预取再投影一次 query。

## §3　上一拍挑页，下一拍先用；偏离太大才纠错

作者在 Llama-3.1-8B-Instruct 的长生成和 DeepSeek-R1-Qwen-14B 的推理任务里，比较同一层、同一 attention head 在相邻解码步的 query。图 3（PDF 第 5 页）里，大多数头在 13,000 个生成 token 上的平均余弦相似度超过 0.9，但个别步会突然下降，不同头下降的时刻也不一样。高均值给了预取一个理由，低相似度的少数步决定了纠错不能省。

FreeKV 用当前 query 给页打分，同时用上一步已经拉回的页做本步 attention。本步新选的页通常留给下一步，这样选页和搬运就有机会与当前层的 attention、FFN 及下一层的 QKV 投影重叠。选页只看 key 的逐维最小值和最大值摘要。同一个 GQA 组的 query heads 各自计算页分数，沿页维度做 softmax，再对组内概率取均值。共享一个 KV head 的 query heads 用同一份页列表，不必各搬各的。

纠错检查的是组内相邻 query 的平均余弦相似度，不直接比较两个 top 页集合。低于阈值的 KV head 必须等本步按新 query 选出的页；其余头继续用已经到位的页。只要有头触发纠错，选页就对所有头合并发起，避免把 GPU 工作拆成两次；搬运才按头分流，纠错头先搬，其他头的页随后预取。图 4（PDF 第 6 页）里，阈值是 0.8，均值为 0.75 的头等新页，另外两个均值为 0.85 的头照常复用。

## §4　CPU 按 head 排，GPU 按 token 排

GPU 保留上一拍的 query、页摘要和选中的 KV 页，主存保留完整 KV。GPU 用 NHD，保持 QKV 投影得到的 token 优先布局；卸载时把页转成 HND，在主存里让同一 KV head 的多个 token 连续存放。以 head 维度 128、FP16 和每页 32 token 为例，NHD 下一个 head 的单个 K 或 V 片段只有 256 B；HND 下单个 K 或 V 的整页是 8 KiB，主存布局把 K、V 放在一起时一次可搬 16 KiB（图 5–6，PDF 第 7 页）。召回到 GPU 后仍需转换回 NHD。两个 GPU 缓冲区交替工作，一块在转换上一批数据，另一块接下一批。

## §5　质量接近完整 KV，延迟收益主要来自长解码

下面都是作者报告的结果。质量实验和延迟实验的设置不同，不能把一组的输入输出长度套给另一组。

| 质量实验 | 条件与结果 |
| --- | --- |
| 长输入：LongBench v2，表 2（PDF 第 8 页） | 输入截断到 64K token，贪心解码。Llama-3.1-8B-Instruct 的整体准确率与完整 KV 同为 29.22%；Qwen-2.5-7B-Instruct 从 27.44% 降至 26.84%，14B 则从 33.40% 升至 34.19%。正文说整体准确率最多相差 0.6 个百分点，按表中 14B 数据算是 0.79 个百分点。 |
| 长生成：LongGenBench，表 2（PDF 第 8 页） | 最多生成 16K token，由 Qwen-3-32B 判分。以 Llama-3.1-8B-Instruct 为例，FreeKV 的子任务完成率低于完整 KV（78.03% 对 80.03%），完成率乘准确率略高（27.62% 对 26.82%）。 |
| 长推理：AIME24，表 3（PDF 第 9 页） | 全部题目，每题采样 8 次、每次最多生成 16K token。DeepSeek-R1-Qwen-7B 的 pass@8 与完整 KV 同为 83.33%，但单次样本的平均正确率从 56.66% 降到 52.92%。能在八次里答对一次，不代表每次都一样可靠。 |

延迟实验用单张 NVIDIA A100 40 GB、AMD 7302 CPU 和 PCIe Gen4，测试 batch 1、2、4。FreeKV 的页大小是 32 token，KV 预算参数为 2,048 token，attention sink 与局部窗口各 512 token；长输入和长生成分别用 0.8、0.9 的纠错阈值。图 7（PDF 第 10 页）的倍数是 **端到端延迟比**，含 prefill 和 decode：

| 模型（batch 4） | 32K 输入 / 512 输出 | 600 输入 / 16K 输出 |
| --- | ---: | ---: |
| Qwen-2.5-7B-Instruct，相对 ArkVale | 5.76× | 7.92× |
| Llama-3.1-8B-Instruct，相对 ArkVale | 10.03× | 13.74× |

Quest 在 32K 输入、batch 4 的例子中显存不足，未纳入延迟比较。附录 A（PDF 第 15 页）还说明，长生成对照中的 ShadowKV 是作者修改过的版本，会周期性更新 SVD；若与上游实现的结果对照，要先核对这个差异。

同一套硬件上，附录 C.2 图 9（PDF 第 17 页）拆开测了 Llama-3.1-8B-Instruct 的长生成（600 输入、16K 输出、batch 4）：不作优化 9,910.3 秒，换混合布局 940.1 秒，再加双缓冲 776.0 秒，最后启用推测检索 413.1 秒。这是逐步增加功能的消融，和图 7 的 ArkVale 基线不同。先把零碎搬运变成连续传输，才更有可能在计算结束前把预取做完。

## §6　哪些结论值得带走？

FreeKV 无需重新训练模型，但复用前一步的页属于近似；表 3 也有分数下降。附录 B.3 的表 7（PDF 第 16 页）里，DeepSeek-R1-Qwen-7B 的 GPQA 平均正确率在不纠错时为 36.00%，把阈值提高到 0.9 后是 39.50%。同一节说 max pooling 会触发更多纠错；按正文的低于阈值规则，对同一批相似度，最大值不小于均值，单次判定只会相同或更少。这句描述不能直接从算法推出，表 6 也没列触发次数。

固定预算限制的是每步选中、留在 GPU 的 KV 数据；主存里的完整历史 KV 和 GPU 上的页摘要仍随上下文增长。移到端侧，先量一次页召回要多久，再看这一层的计算能盖住多少等待。独显笔记本仍会遇到主存到显存的传输，Orin 的 CPU 与 GPU 则共享物理内存，先看布局转换和内存争用。论文未在这两类设备上给出实测，本笔记也未运行论文代码。
