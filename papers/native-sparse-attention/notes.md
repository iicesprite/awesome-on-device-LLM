# Native Sparse Attention: Hardware-Aligned and Natively Trainable Sparse Attention

来源：[ACL 2025 正式版](https://aclanthology.org/2025.acl-long.1126.pdf)。阅读范围为正文 §§1–5、Limitations 和附录 C–F；以下页码均为论文页码。读这篇主要想弄清两件事：模型怎样在预训练时学会稀疏地读历史，以及少读的 KV 能换来多少实际加速。

## 1. 为什么把稀疏做进训练（§1、§2.1）

长文本 prefill 和训练要计算大量 query–key 配对；逐 token decode 的压力更多来自反复把历史 KV 从显存读给注意力算子。两者都能从稀疏中获益，但选出更少的 token 不等于按比例省时。如果每个查询头都要在显存里零散地抓不同的 token，GPU 仍要做许多不连续的读操作，同一份 KV 也可能被重复加载。

另一层问题在模型本身：先用全注意力训练，推理时再裁掉大部分连接，改变了模型训练时所见的上下文。NSA 从预训练开始就用同一套稀疏注意力；选块规则与 KV 的读取方式也一起设计。

## 2. 先粗读，再决定哪里值得细读（§2.2–2.3，图 2）

同一个 query 走三路注意力，每一路独立做 softmax。门控由输入特征经过 MLP 和 sigmoid 得到，最后加权合并三路输出（式 5）。

1. **压缩。** 在已完成的历史片段上用滑动块取样，加入块内位置编码，通过可学习的 MLP 把每块的 K、V 各压成一个向量。实验取块长 32 token、步长 16 token，相邻块有重叠。查询一直能看到历史的粗粒度表示。
2. **选择。** 直接复用压缩注意力产生的权重，按块的对应位置把它们汇总到 64-token 的选择块；GQA 组内再把各查询头的分数相加。然后对每个 query、每个 KV 组选 top-16 块（实验配置含固定激活的 1 个开头块、2 个局部块）。命中后读取的是选择分支中逐 token 的 K、V，再算一次注意力。块摘要在这里负责导航，细节由原始粒度的 KV 提供。
3. **滑窗。** 另一路专看最近 512 token。论文给三路各自的 KV 表示，希望容易学会的近邻模式不要抢占压缩和选块分支的训练信号。

“可训练”不意味着 hard top-k 的索引可微。压缩分支本身参与预测，压缩表示能从模型损失中学到东西；选择分支顺手复用这些分数，不必另训一个索引器。附录 E（图 7）在相近架构的 3B 模型上试过独立打分的两种做法：用全注意力块分数作辅助监督，或按 key 的块内极值估分。论文报告，这两种做法的训练损失都高于 NSA。

## 3. 同组查询头共用一次 KV 读取（§2.4，图 3）

普通 FlashAttention 往 SRAM 装相邻位置的 query；但在选择分支中，相邻位置可能挑中完全不同的 KV 块。NSA 把 tile 的另一维用起来：固定一个 query 位置，把同一 GQA 组的查询头一起装入 SRAM。内循环按共享索引从 HBM 读连续的 KV 块，一块数据给组内多个查询头用。内核 tile 尺寸整除选择块长度，且每个 query 要处理的块数有上限，方便划分并行任务。压缩和滑窗分支则可沿用 FlashAttention-2 的计算方式。

## 4. 模型质量：看同骨架、不同注意力的对照（§3）

作者使用同一套 GQA + MoE 骨架（总参数 27B、激活参数 3B），分别预训练 Full Attention 与 NSA。按 §3.1，先用 8k 长度的文本预训练，再用 YaRN 适配 32k 长度并继续训练、微调。预训练 token 总量有两处说法：§3.1 写 270B，引言（论文第 23079 页）写 260B，论文没有解释差异。

## 5. 算子实测与 decode 估算分开看（§4）

作者的算子实验使用一套 8 张 NVIDIA A100 的系统，双方均为 Triton，基线是 Triton 版 FlashAttention-2。双方各用 4 个 GQA 组、每组 16 个查询头，Q/K head dim 为 192、V head dim 为 128。图 5 给的是注意力算子时间和倍率，§4.1 未给出 batch 大小或披露图中的多卡分工。

| 序列长度（token，按图 5 标注） | 前向算子加速 | 反向算子加速 |
| --- | ---: | ---: |
| 8k | 2.1× | 1.1× |
| 16k | 3.8× | 2.0× |
| 32k | 6.3× | 3.4× |
| 64k | 9.0× | 6.0× |

单 token decode 的 **11.6×** 则来自表 4（论文第 23084 页）的等效 KV 加载量：缓存有 65,536 token 时，Full Attention 每次注意力需读 65,536 个 token 位置，NSA 估为 5,632 个，二者相除约为 11.6。表中把它标作预期加速；§4.2 未另给逐 token 延迟或吞吐实测及 batch。前向内核的 9.0× 也不能直接用作整模型的 prefill 时间倍率。

## 端侧还要算存储账

NSA 节省的是每个 query 读过的原始 KV。某块现在没被选中，下个 query 仍可能要读它；论文没有把这种稀疏当作永久淘汰或低比特量化。随着上下文变长，压缩分支仍要扫过约每 16 token 一个的摘要，decode 的访问量并非常数。若端侧已经放不下原始 KV，仍需另做驻留、卸载或压缩方案。

对小显存设备，更有用的对照是固定模型、batch 和上下文，把选块、KV 读取、注意力、其余模型计算分开计时，再看 TTFT 和逐 token 延迟。A100 上验证了按 GQA 组复用 KV 的做法；论文没有端侧实测，本笔记也未运行代码。
