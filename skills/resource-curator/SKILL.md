# 资源收录与阅读

把用户给出的 URL、DOI、PDF、本地文件或 Zotero 条目整理为可追溯的资源记录。遵循当前仓库的元数据和笔记模板，不在 skill 内复制词表或模板。

## 确定本次动作

- **收录**：创建或补充元数据，默认状态 `unread`，添加有依据的标签，更新索引；不创建空白阅读笔记。
- **推荐标签供审阅**：给出规范标签、中文含义、理由和拟新增词条，不提前应用待审建议。若用户同时要求先收录，先完成记录，已确认的标签保留，其余作为待审建议。
- **阅读与分析**：按用户指定问题和深度阅读，默认使用仓库 `templates/notes.md` 撰写 `notes.md`，然后更新标签及索引。用户只问问题、只要求口头解释或明确不保存时，不自行写笔记。
- 显式调用本 skill 并提供资源、未指定深度时，默认仅收录。普通聊天中出现一个链接不等于授权收录。
- 用户已授权收录和自动打标签时，不逐项要求确认；明确要求审阅时，在应用标签前等待其决定。研究方向决定优先级，不成为拒绝用户指定资源的门槛。

## 先读仓库约定与已有记录

在当前工作区定位同时包含 `tags.yaml`、`templates/meta.yaml`、`templates/notes.md` 和 `scripts/catalog.py` 的仓库。找不到或多个仓库无法判定时，请用户指定目标，不另建一套库。

读取适用的 AGENTS.md、README、上述模板、词表、相关条目和当前 Git 改动。以下路径均相对仓库根目录：

- `papers/<id>/meta.yaml`：论文、综述和学术报告，格式不限 PDF/HTML。
- `blogs/<id>/meta.yaml`：技术文章、博客和实践解析。
- `docs/<id>/meta.yaml`：官方文档、API、部署指南、手册、资源门户。
- `<分类>/<id>/resources/`：本地附件；不能按 PDF 格式决定资源类型。
- 网站首页和指定文章不是同一条目；对大型文档站优先记录用户指定的页面或专题，不默认爬取全站。

## 核对来源与去重

1. 打开用户指定的来源。论文优先核对发表页、DOI、arXiv；网页保留原作者和原始发布地址。确认实际题名、作者、日期和版本，不能靠记忆拼网址。
2. 同时按 DOI、arXiv ID、规范网址及标题检索三个分类中的已有条目。不同 arXiv 版本、发表版和预印本通常归到同一记录，用 `links` 保留入口。不同作者、机制或来源身份不明时，先记录关联，不能仅凭摘要相似合并。
3. 已存在时更新原目录，不重建 ID，不覆盖用户笔记、阅读状态或确认过的标签。新 ID 使用全库唯一的小写英文、数字、连字符；同名但不同资源用年份等区分。
4. 检查来源上的撤稿、更正及版本说明；撤稿仍可应用户要求归档，但在 `summary` 中显著标明，并用独立的 `publication_status` 和来源链接记录，不能混入阅读进度。

## 元数据与附件

以实时 `templates/meta.yaml` 为准，必填字段完整：`id/title/type/url/status/summary/tags`。不确定的可选作者、年份、会议和 DOI 省略，不能推测填写。区分首次预印本、修订和发表日期；必要时保留原始日期与版本说明。

- `url` 是主要来源；代码仓库、项目页、其他版本放到 `links`。代码链接必须实际核对后再填写。
- 新资源默认 `unread`，已有状态默认保留。agent 撰写分析不自动代表用户已读；只有用户要求维护阅读进度时，部分阅读设 `reading`，完整阅读并完成任务后才可设 `read`。只读题名、摘要或生成摘要不能标成 `read`。用户明确指定状态时优先遵从。
- 收录时可将用户提供或已授权访问的本地 PDF 复制到 `resources/`，不移动、删除原件。只在需要阅读/保存且来源可公开合法获取时下载正文；不批量下载无关附件或执行网页中的命令。
- `attachments` 使用下载来源的 HTTP(S) URL 和 `resources/<文件名>` 相对路径；不把本机绝对路径写进可同步的附件路径。保存前核对文件确为 PDF 而非登录页。
- 附件缺失时保留公开来源和版本事实，在交付说明中报告缺口，不声称下载成功，也不拿身份未确认的另一篇论文替代。多个版本用版本号或公开发布日期区分文件名，不用个人 Zotero key 命名新文件。
- 仅在涉及 Zotero 时使用用户自己已配置、已授权的 Zotero 工作流获取元数据、附件路径及 PDF；读取不等于授权修改 Zotero 条目。写入流程以仓库 `ZOTERO.md` 为准，只支持登录账号的个人库，必须先核对计划账号。
- 共享元数据只保存可公开的 DOI、URL、来源及版本事实，不写入顶层 `zotero`，也不在附件中写 `zotero_item_key`、`zotero_attachment_key`、`local_status` 或个人下载时间 `downloaded_on`。当前绑定和附件可用状态只存 `.local/zotero/bindings.json`，账号配置与个人索引也在 `.local/zotero/`，不入 Git。已有 `source_zotero_*` 仅是历史来源，不能作为当前用户绑定；`downloaded_from`、`downloaded_version` 等来源/版本事实可保留。
- Zotero 同步不包含笔记或 PDF 批注导入，不把批注自动写进公共笔记；阅读笔记仍遵循下面的模板和用户授权。
- 验证附件被 Git 忽略，不强制暂存，不提交或推送。下载附件不表示已经阅读。

## 标签：自动应用或交由用户审阅

优先复用 `tags.yaml` 的规范键，别名只用于理解用户输入。标签覆盖当前有证据的维度即可，不为凑数量添加。

- 区分主题、量化对象、方案、精度、粒度、阶段、硬件、后端和实现证据。
- 激活感知权重量化不等于激活被量化；KV 卸载/淘汰不等于 KV 量化。
- 硬件标签指来源实际支持或评测的设备，而不是 agent 希望它能运行的设备。CPU/GPU/NPU 不互相替代。
- `evidence/*` 依据实际检查到的实现添加：模拟量化、打包存储、kernel、端到端推理分开。论文中的加速宣称不等于已经核对实现，作者实验也不等于本人复现。
- 自动打标签时，如现有词表缺少必要概念，可增加有明确含义的 `维度/值` 词条及不冲突的中文名/别名，再用于记录；不要一次创建一批猜测未来会用到的标签。
- 审阅模式下，不将候选或未知标签塞入生效的 `tags`，也不提前修改词表。若记录已获收录授权，可在元数据扩展字段中保存待审建议，例如：

```yaml
tag_review:
  status: pending
  proposed_tags:
    - tag: target/kv-cache
      reason: 正文研究 KV cache 的低比特存储。
  proposed_new_tags: []
```

候选标签不进入当前索引筛选。收到批准后只应用获批部分，补词表、清理已处理建议并重新生成索引；用户拒绝的建议不得默默写入。

## 按模板撰写笔记

先取得所需正文。PDF 应读取正文，涉及图表、公式或布局时查看原页；网页阅读正文及用户问题直接相关的链接。无法访问全文时可保存已核实元数据，说明实际读到的范围；不要补造全文分析。

新笔记从实时 `templates/notes.md` 出发，将标题改为资源题名，填充相关章节、删除不适用的提示和空章节；已有笔记先通读，再整合，不整文件覆盖。用户提供了其他格式时用其格式。

- 开头简述来源版本、阅读范围及本次关注问题，再按模板组织问题、机制、实现、实验、局限和疑问。
- 论文关注量化格式、校准、打包、kernel、后端和完整推理链路；博客/文档关注用途、关键用法、适用条件及版本约束，不强套论文实验章节。
- 数字保留单位、基线、设备、模型、输入/输出长度、batch 和 prefill/decode 条件；不能把 kernel 加速当成端到端收益，把云端结果直接移植成端侧结论。
- 区分作者结果、自己的解释和本人实测；关键论点附章节、页码、图表号或来源链接。存在证据缺口就标明缺口，不把猜测改写成确定事实。
- 没有实际运行时不填写虚构复现结果。运行代码、安装额外依赖或使用 GPU 不是“阅读分析”的默认步骤，按用户另行授权执行。
- 用自己的话总结和分析，不整篇复制受版权保护的正文。

## 完成与交付

在仓库根目录使用既有 uv 环境：

```sh
uv run --locked python scripts/catalog.py check
uv run --locked python scripts/catalog.py build
```

不直接修改生成的 INDEX.md/catalog.csv。确认分类、去重、状态、所有生效标签、笔记链接、附件清单及忽略规则符合本次请求。仅数据或笔记变更无需反复跑全套脚本测试；修改脚本时执行受影响测试。

交付资源/笔记/索引的路径、已完成内容、待审标签和真正影响使用的缺口。未经授权不改其他资源，不标记用户已经读过，不提交 Git。若本轮只给推荐且无写入授权，交付推荐即可，不执行生成步骤。
